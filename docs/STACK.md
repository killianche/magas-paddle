# Технический стек — ПРЕДЛОЖЕНИЕ, ждёт подтверждения заказчика

Статус: **предложено 2026-08-31, не утверждено.** Макеты от стека не зависят, поэтому
дизайн идёт параллельно, не дожидаясь этого решения.

## Общий принцип
Один язык — **TypeScript** — в приложении, бэкенде и админке. На проекте такого размера это
буквально вдвое меньше работы: типы API описываются один раз и переиспользуются везде,
рассинхрон контракта между клиентом и сервером становится ошибкой компиляции, а не багом в проде.

## 1. Мобильное приложение: React Native + Expo

**Почему не нативно (Swift + Kotlin):** две отдельные кодовые базы, двойная стоимость,
двойной срок. Для приложения записи на корт нативные API почти не нужны.

**Почему Expo, а не «голый» React Native:**
- **EAS Build собирает iOS без Mac.** Это страховка: Apple не продаёт технику в России
  с марта 2022, Mac есть только через параллельный импорт. Даже если Mac есть, иметь
  запасной путь сборки полезно.
- Expo Router, expo-image, Reanimated, expo-notifications — всё нужное из коробки,
  без ручной возни с нативными проектами.

**Почему не Flutter (честно, это близкий выбор):**
- Плюс Flutter: SDK RuStore для Flutter чуть аккуратнее упакован (`flutter_rustore_push` на pub.dev),
  и рендеринг пиксельно одинаков на обеих платформах.
- Минус Flutter: **iOS собирается только на macOS**, аналога EAS Build нет. И Dart —
  ещё один язык поверх TypeScript, которым уже написаны бэкенд и админка.
- **Вывод: берём Expo. Если заказчик предпочитает Flutter — скажите, переиграем сейчас, потом дорого.**

**Известная сложность:** SDK RuStore (`react-native-rustore-push`) — не Expo config plugin.
Понадобится `expo prebuild` и собственный dev client. Решаемо, но заложить в срок.

**Требования к реализации, вытекающие прямо из исследования отзывов:**
- **Никакого WebView.** Отзыв про CourtReserve: *«почти уверен, что это webview с обёрткой —
  плохая производительность, тормозной скролл, задержки при нажатии на что угодно»*.
  Плюс RuStore отклоняет WebView-обёртки без собственной ценности.
- **Никакой заставки при запуске.** Главный экран рисуется мгновенно из локального кэша
  и обновляется в фоне.
- **Pull-to-refresh обязателен** плюс автообновление при возврате в приложение.

## 2. Бэкенд: Node.js + NestJS + PostgreSQL

- **NestJS** — структура, которая переживёт передачу проекта другому разработчику.
- **Prisma** как ORM, миграции в репозитории.
- **PostgreSQL** — свой, в Docker Compose на том же VPS (обоснование в docs/RESEARCH-BACKEND.md).
- **Redis** — кэш и очередь отложенных задач (напоминания о брони).

### Защита от двойной брони — на уровне базы, а не приложения
Это самое важное техническое решение всего проекта. Из отзывов: *«Оба раза деньги списали,
а корт показан свободным»*, *«Доступность кортов неточная»*.

Проверка «свободен ли слот» в коде приложения **не работает** под гонкой запросов. Правильное
решение — ограничение целостности в самой PostgreSQL:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

ALTER TABLE booking ADD CONSTRAINT booking_no_overlap
  EXCLUDE USING gist (
    court_id WITH =,
    tstzrange(starts_at, ends_at, '[)') WITH &&
  ) WHERE (status <> 'cancelled');
```

База физически не даст создать две пересекающиеся брони на одном корте, сколько бы
одновременных запросов ни пришло. **Именно поэтому нужен свой PostgreSQL, а не управляемый
у Beget: там расширения ставятся только через тикет в поддержку.**

## 3. Админка: React + Vite (десктопный веб-сайт, не приложение)
- React + TypeScript + Vite, TanStack Query, компонентная библиотека.
- Ядро админки — **сетка «7 площадок × время» с drag-выделением**: занять, освободить,
  заблокировать площадку, подтвердить входящую заявку.
- Аутентификация менеджеров отдельная от приложения.
- Отдаётся тем же nginx с того же VPS по поддомену.

## 4. Инфраструктура
- **Beget VPS 2 CPU / 4 ГБ / 40 ГБ ≈ 990 ₽/мес**, Ubuntu 24.04, Docker Compose.
- **Beget S3** для фотографий кортов и обложек турниров, ~2,1 ₽/ГБ/мес.
- nginx + Let's Encrypt (бесплатно, автопродление).
- **Свой `pg_dump` по cron в S3** — автоматические бэкапы Beget работают «раз в 2–5 суток,
  как получится», на это полагаться нельзя.
- CI: GitHub Actions → SSH → `docker compose up -d`. Через зеркало `dockerhub1.beget.com`,
  потому что Docker Hub блокирует российские IP с 2024-05-30.

## 5. Уведомления
Отправитель пушей — **отдельный модуль за интерфейсом**, с поддержкой прокси через переменные
окружения. Причина: `api.telegram.org` уже не работает из российских ЦОД, доступность
APNs и FCM с Beget не подтверждена.
**Перед написанием кода пушей — тест доступности с арендованного на сутки VPS** (~11 ₽),
команда в docs/RESEARCH-BACKEND.md.
