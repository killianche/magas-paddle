# Нативные возможности iOS: что реально доступно из Expo

Проверено 31.08.2026 прямыми запросами к докам Apple, реестру npm и GitHub API.
Метки: **[П]** подтверждено, **[НП]** НЕ ПРОВЕРЕНО.

## Базис [П]
- **Expo SDK 57.0.0 / React Native 0.86** — актуальные версии. https://docs.expo.dev/versions/latest/
- RN 0.82+ работает только на новой архитектуре, но слои совместимости сохранены:
  «We will keep the interop layers in the codebase for the foreseeable future».

---

## ★ Главная находка: виджеты и Live Activities — БЕЗ нативного кода [П]

**`expo-widgets` 57.0.15** (обновлён 2026-08-28, ~598 тыс. загрузок в месяц) официально покрывает
«iOS home screen widgets **and Live Activities** using Expo UI components, **without writing
native code**». https://docs.expo.dev/versions/latest/sdk/widgets.md

Поддерживаемые размеры: `systemSmall/Medium/Large/ExtraLarge`, `accessoryCircular/Rectangular/Inline`
(последние три — экран блокировки). Есть `addUserInteractionListener` для нажатий внутри виджета.

**Что это даёт нашему приложению — и это сильные вещи:**
1. **Виджет «ваша ближайшая бронь»** на домашнем экране и на экране блокировки.
2. **Виджет «свободно сейчас: 4 из 7»** — человек видит загрузку клуба, не открывая приложение.
3. **Live Activity «корт через 30 минут»** — живёт на экране блокировки и в динамическом острове,
   ведёт обратный отсчёт до игры. Для приложения записи это ровно тот случай, ради которого
   Live Activities придуманы.

**Ничего из этого не требует Swift.** Это самый выгодный по соотношению «эффект/затраты» пункт
всего списка. **Рекомендую взять в план.**

## Apple Wallet — бронь как карта в кошельке [П] выполнимо

**Клиентская часть работает уже сегодня.**

| Пакет | Версия | Загрузок/мес | Плагин Expo |
|---|---|---|---|
| **`react-native-wallet-manager`** | **2.1.0** (2026-03-03) | **96 273** | нет, права прописываются вручную |
| `@premieroctet/react-native-wallet` | 1.0.2 | 5 235 | нет, но это Expo-модуль |
| `expo-passkite` | 1.0.2 | 23 | **есть**, плюс серверный подписчик — но 0 звёзд, не проверен |

**Серверная часть — вот где работа.** Нужно подписывать `.pkpass`:
- Библиотека **`passkit-generator` 3.5.8** (обновлена 2026-08-28, **1,18 млн загрузок в месяц**) — зрелая.
- Требуется: **Pass Type ID**, сертификат Pass Type ID и приватный ключ, сертификат WWDR,
  подпись PKCS#7 файла `manifest.json`. Ключ надо безопасно хранить на сервере.
- Официальная инструкция: https://developer.apple.com/documentation/walletpasses/building-a-pass

**Важная деталь [П]:** право `com.apple.developer.pass-type-identifiers` нужно
**только для чтения и удаления** карт. Чтобы просто **добавить** карту — не нужно.
EAS Build умеет проставлять это право автоматически.

**Оценка:** выполнимо, но требует Apple Developer аккаунта, сертификатов и серверной подписи.
**Вторая очередь, не первая.**

## Siri и App Intents — «Сири, забронируй корт» [П] выполнимо, но зыбко

**Жёсткие ограничения [П]:**
- App Intents — **только Swift**. У протокола `AppIntent` в документации Apple указан
  единственный вариант языка: `swift`. Обойти нельзя.
- Фразы и типы намерений — **метаданные времени сборки**, а не рантайма.
  Создать их из JavaScript на лету невозможно.
- Код должен быть **в основном таргете приложения**, не в поде и не в расширении.
- iOS 16.4+, в Expo Go не работает.

**Состояние обёрток — честно: все свежие и почти без пользователей.**
`@weavolve/react-native-siri` 0.1.1 — 64 загрузки, 0 звёзд.
`@avasapp/react-native-app-intents` 0.2.6 — 687 загрузок, 2 звезды.
Старый `react-native-siri-shortcut` 3.2.4 не обновлялся с декабря 2023.

**★ Но есть важное:** Expo делает **свой первый официальный модуль `expo-app-intents`**.
Версия 0.1.0, автор «650 Industries» (это сама Expo), код влит в основную ветку 26–27 августа 2026,
документация помечена `isAlpha: true` от 27.08.2026.
**В npm пока пустышка 0.0.1 — установить нельзя.**

**Оценка:** ждать `expo-app-intents`. Ставить сейчас библиотеку с двумя звёздами в продакшен
клубу — плохая идея. **Отложить.**

## Пункты управления (Control Center) [П] только через ручной Swift
Требуют расширения-виджета плюс написанного руками SwiftUI `ControlWidget` и
`ControlConfigurationIntent`. `expo-widgets` их **не покрывает** — проверено по полному тексту
документации. Единственный путь — `@bacons/apple-targets` 5.0.0 и Swift вручную.
Ни одной обёртки на TypeScript не существует. **Пропустить.**

## Фокус-фильтры ❌ пути из React Native нет
`SetFocusFilterIntent` — только Swift. Поиск по npm и GitHub даёт **ноль результатов**.
Ни Expo, ни `@bacons/apple-targets` их не поддерживают. **Пропустить.**

## Итог: что берём

| Возможность | Решение | Когда |
|---|---|---|
| **Виджет «ближайшая бронь»** | `expo-widgets`, без Swift | **Первая очередь** |
| **Виджет «свободно сейчас»** | `expo-widgets`, без Swift | **Первая очередь** |
| **Live Activity «корт через 30 минут»** | `expo-widgets`, без Swift | **Первая очередь** |
| Бронь картой в Apple Wallet | `react-native-wallet-manager` + `passkit-generator` | Вторая очередь |
| «Сири, забронируй корт» | Ждать официальный `expo-app-intents` | Отложить |
| Пункты управления | Ручной Swift | Пропустить |
| Фокус-фильтры | Пути нет | Пропустить |

**Вывод, который стоит проговорить:** три самые заметные для пользователя вещи — виджеты и
живая активность — доступны **без единой строки нативного кода** и покрываются официальным
модулем Expo. Именно они превращают приложение из «сайта в обёртке» в то, что живёт на телефоне.
Это же прямо работает на правило Apple 4.2, по которому отклоняют «переупакованные сайты».
