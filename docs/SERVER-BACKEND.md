# Бэкенд на сервере

## Решение по Q34: размещаем на том же сервере

Измерено 3 сентября 2026, а не прикинуто на глаз:

| Ресурс | Всего | Занято чужим Supabase | Свободно |
|---|---|---|---|
| Память | 3,8 ГБ | 1,8 ГБ | **2,0 ГБ** |
| Диск | 48 ГБ | 16 ГБ | **32 ГБ** |
| Процессор | 2 ядра | load 0,25 | почти простаивает |

Наша база и кэш после запуска съедают **33 МБ** из 2 ГБ. Место есть с большим запасом,
отдельный сервер сейчас не нужен.

## Как отделено от соседнего проекта

- Отдельный проект Compose `magas-padel`, свои сеть и тома
- Контейнеры `magas-db`, `magas-cache` — имена не пересекаются
- Порты слушают **только localhost**: `127.0.0.1:5433` и `127.0.0.1:6380`.
  Снаружи база недоступна вообще, ходить через SSH-туннель
- Ограничения памяти: 640 МБ базе, 192 МБ кэшу — чтобы при всплеске
  не задеть соседний проект
- Чужие тома `supabase_*` не трогаются

## Что стоит

`/opt/magas-padel/` — compose, схема, копии базы, `.env` с паролем (права 600).
В репозитории — `server/`, пароль туда не попадает.

| Что | Образ | Порт |
|---|---|---|
| PostgreSQL 17 | `postgres:17-alpine` | 127.0.0.1:5433 |
| Redis 7 | `redis:7-alpine` | 127.0.0.1:6380 |

## Защита от двойной брони — проверена, а не обещана

В таблице `bookings` стоит ограничение уровня СУБД:

```sql
EXCLUDE USING gist (
  court_id WITH =,
  tstzrange(starts_at, ends_at, '[)') WITH &&
) WHERE (status <> 'cancelled')
```

Проверка живая, прогнана на сервере:

| Случай | Ожидание | Результат |
|---|---|---|
| Первая бронь 18:00–19:00 | пройдёт | прошла |
| Ровно то же время | отказ | **отказано** |
| Пересечение 18:30–19:30 | отказ | **отказано** |
| Встык 19:00–20:00 | пройдёт | прошла |
| Отменить первую и занять её время | пройдёт | прошла |

Это значит: даже если два человека нажмут «Записаться» в одну миллисекунду
или кто-то полезет в базу мимо приложения, вторая запись не появится.

## Копии базы

`/opt/magas-padel/backup.sh` каждый день в 4:20, хранятся 14 последних,
лог в `/var/log/magas-backup.log`. Первая копия сделана.

**НЕ ПРОВЕРЕНО:** восстановление из копии на чистой базе. Нужно прогнать до запуска в работу.

## Чего ещё нет

- API (NestJS + Prisma) — база готова, приложение пока работает на заглушках
- Наполнение справочника площадок реальными данными клуба
- Копии базы уезжают только на этот же сервер: если диск умрёт, умрут и они

## Почему приложение работало только через VPN (08.09.2026)

Заказчик сообщил: в России приложение не грузится без VPN. Разобрано.

### Что проверено

| Что | Результат |
|---|---|
| Где стоит сервер | `217.114.8.196` — **Beget, Россия**. Маршруту из России блокировать нечего |
| Разрешение имени | Яндекс, Ростелеком, Google, Cloudflare — все дают верный адрес. **DNS ни при чём** |
| Ответ по голому адресу | `http://217.114.8.196/` и HTTPS — **200** |
| Сертификат | Let's Encrypt, действителен до 30 ноября 2026 |

### Вывод

Единственное необычное здесь — само имя. Мы сидели на
`padel.217-114-8-196.sslip.io`. Это бесплатный сервис подстановки любого IP
в имя, делегированный на серверы **nip.io**. Такие сервисы используют для
обхода ограничений, и в России их режут по имени соединения: техника
блокировки видит `sslip.io` в запросе TLS и рвёт связь ещё до сервера.

**НЕ ПРОВЕРЕНО:** доказать это с нашего VDS нельзя — он стоит в США, отсюда
всё открывается. Решающая проверка со стороны заказчика: открыть с телефона
**без VPN** `http://217.114.8.196/`. Открылось — виновато имя; не открылось —
заблокирован сам адрес, и разговор про Beget и смену IP.

### Как чинится

`scripts/set-domain.sh <домен>` делает всё: проверяет, что домен указывает
на наш сервер, добавляет имя в nginx (старое **не убирает** — по нему ещё
ходят ранее собранные версии приложения), выпускает сертификат, переключает
`apiUrl` в приложении, пересобирает и выкладывает.

Перед запуском у регистратора нужна запись **A: <поддомен> → 217.114.8.196**.

Домен `xtrud.pro` заказчика уже живёт на этом же сервере (reg.ru), поэтому
самый быстрый путь — поддомен `padel.xtrud.pro`. Правильный на будущее —
свой домен клуба вроде `magaspadel.ru`.

После переезда не забыть поменять адрес политики конфиденциальности
в App Store Connect: сейчас там `padel.217-114-8-196.sslip.io/privacy.html`.
