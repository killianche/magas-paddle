# Выпуск iOS-сборки

Собирается на macOS-раннере GitHub Actions. Облако Expo не используется:
`expo prebuild` создаёт нативный проект, дальше обычные `xcodebuild` и `altool`.

## Как запустить

**Пушем в ветку:**
```bash
git push origin main:build-ios
```
**Или кнопкой:** вкладка Actions → «iOS TestFlight» → Run workflow.
Кнопка требует права Actions у токена; пуш в ветку — только права на код.

Ход сборки: https://github.com/killianche/magas-paddle/actions

### Как дать приложение друзьям

Выбран путь внутреннего тестирования: до 100 человек, проверка Apple не нужна,
каждый ставит на 30 своих устройств.

**Что это значит на практике.** Внутренний тестировщик — это пользователь вашего
аккаунта App Store Connect. То есть каждого друга придётся завести в аккаунт.
Чтобы это было безопасно, приглашаем с ролью **MARKETING** и доступом
**только к Magas Padel**:

- роль не даёт доступа к сертификатам — иначе ограничение по приложениям
  перестаёт действовать (проверено в документации Apple);
- `allAppsVisible: false` и явный список видимых приложений — соседний
  проект an-Nur друзьям не виден;
- `provisioningAllowed: false` — в сертификаты и профили они не попадут.

Рассылка — `scripts/asc/invite.py`: вписать список и запустить.
Каждому придёт письмо, ему нужен Apple ID с двухфакторной аутентификацией.

Прежняя развилка, для истории:

| Путь | Кому | Нужна проверка Apple | Ограничение |
|---|---|---|---|
| Внутренние тестировщики | до 100 | нет | каждого надо завести **пользователем аккаунта разработчика** — чужим людям туда доступ давать не стоит |
| Внешние тестировщики | до 10 000 | **да** | ссылку или приглашение можно отправить кому угодно |

Для друзей годится только второй путь. Он требует TestFlight App Review,
а чтобы отправить сборку на проверку — обязателен телефон контактного лица.

**Пока проверка не пройдена, друзьям даём веб-версию:**
`https://padel.217-114-8-196.sslip.io/v1/`

Это тот же код, что и в приложении. Открывается в браузере телефона, а через
«Поделиться → На экран Домой» ставится как приложение: своя иконка, полный экран,
без адресной строки. Настроено манифестом `public/manifest.webmanifest`
и обёрткой `app/+html.tsx`.

Чего в веб-версии нет: push-уведомлений и вибрации.

### Публичная ссылка для всех — что мешает

Ссылку, которую можно дать любому человеку, даёт только **внешняя** группа
тестирования, а она требует проверки Apple (TestFlight App Review).

Проверено по документации Apple: *«After you submit your build to TestFlight App Review,
Apple reviews the build and its accompanying metadata»*.

Что уже заполнено через API:
- описание беты и адрес для отзывов
- «что тестировать» для сборки версии 1

Чего не хватает: **телефон контактного лица**. Поле обязательное, сервер отвечает
`You must provide a value for the attribute 'contactPhone'`. Выдумывать номер нельзя —
по нему Apple может позвонить. **ВОПРОС К ЗАКАЗЧИКУ: нужен настоящий телефон.**

## Как это работает

1. `expo prebuild --platform ios` — из `app.json` создаётся папка `ios/`
2. `pod install`
3. Сертификат импортируется во временную связку ключей, живущую один запуск
4. Профиль кладётся в `~/Library/MobileDevice/Provisioning Profiles`
5. `xcodebuild archive` с ручной подписью, затем экспорт `.ipa`
6. `xcrun altool --upload-app` с ключом App Store Connect
7. `.ipa` дополнительно сохраняется артефактом запуска

**Проверено:** `altool` устарел только для нотаризации macOS
([TN3147](https://developer.apple.com/documentation/technotes/tn3147-migrating-to-the-latest-notarization-tool)),
для загрузки в App Store Connect остаётся штатным.

## Первая сборка: что пришлось починить

Пять заходов, каждая ошибка настоящая:

1. **`MAC verification failed during PKCS12 import`** — keychain macOS не принимает
   контейнеры, которые OpenSSL 3 делает по умолчанию (MAC sha256, AES-256).
   Пересобрали с `-legacy`, MAC sha1 и 3DES.
2. **Схема определилась как `contentsdata`** — `ls` без `-d` показывал содержимое
   каталога `.xcworkspace`, а не его имя. Заодно добавили `set -o pipefail`:
   статус `xcodebuild` терялся в конвейере с `xcpretty`, и провал считался успехом.
3. **`RuntimeScheduler cannot be annotated with SWIFT_RETURNS_RETAINED`** —
   раннер по умолчанию даёт Xcode 16.4, он слишком старый для SDK 57.
   Явно выбираем новейший установленный.
4. **Xcode 26.3 тоже не подошёл** — та же ошибка Swift/C++. Перешли на образ `macos-26`,
   там Xcode 26.6.
5. **`no member named 'executeSync' in worklets::WorkletRuntime`** — `expo-modules-core`
   ждал API, которого нет в установленной версии worklets. `expo install --fix`
   поднял expo до 57.0.19, core до 57.0.15.

Сборка №6 прошла целиком: архив, `.ipa` 17 МБ, загрузка без ошибок,
`UPLOAD SUCCEEDED`. В App Store Connect состояние **VALID**.

Создана внутренняя группа тестирования «Команда клуба» с доступом ко всем сборкам,
владелец аккаунта добавлен тестировщиком.
