### Страны: как оказалось

`GET /v2/appAvailabilities` отдаёт 403 не из-за прав, а потому что коллекция
не читается: `Allowed operations are: CREATE, GET_INSTANCE`. Создать можно,
но сервер требует перечислить **все 175 стран разом**, каждую отдельной
записью в `included` с временным идентификатором вида `${local-id}`.
Сделано: Россия включена, остальные выключены.

### Анкета App Privacy: почему не через API

Проверены все правдоподобные адреса — сервер отвечает не «нет доступа»,
а «маршрута не существует»:

```
404 POST  /v1/appDataUsages                 The resource 'v1/appDataUsages' does not exist
404 GET   /v1/appDataUsagesPublishState     ... does not exist
404 GET   /v1/appDataUsageCategories        ... does not exist
404 GET   /v1/appDataUsagePurposes          ... does not exist
```

Для сравнения: там, где ресурс существует, но операция запрещена, Apple
отвечает 403 с пояснением — как было с доступностью. Здесь именно 404,
то есть в API этого раздела нет вовсе. Заполняется только в веб-интерфейсе.

**Что нажать:** App Store Connect → Magas Padel → **App Privacy** →
«Data Not Collected» → **Publish**.

Если анкета спросит про имя и телефон при записи на корт — это
Contact Info → Name, Phone Number, назначение App Functionality,
связь с личностью есть, отслеживания нет.

После этого версия становится отправляемой, и остальное я довожу через API.

## НЕ ДЕЛАТЬ, пока не закрыто — содержательное

Это важнее технических полей.

**1. В приложении выдуманные данные клуба.** Цены 3 000 / 4 500 ₽, часы 09:00–24:00,
названия площадок, фотографии чужих кортов. Человек скачает приложение реального
клуба и увидит неверные цены. Кроме риска отклонения по правилу 2.3 (точность
метаданных), это просто вводит людей в заблуждение.

**2. Заявка никуда не уходит.** Бэкенд не подключён: запись живёт в памяти телефона.
Человек «запишется», придёт к назначенному времени — а его никто не ждёт.
База с защитой от двойной брони уже поднята, но API между приложением и базой
ещё не написан.

**Порядок, при котором публикация имеет смысл:**
1. Написать API и подключить приложение к базе
2. Получить от клуба настоящие цены, часы, названия, фотографии
3. Проверить сквозной сценарий на живых данных
4. Тогда публиковать

До этого приложение можно показывать через TestFlight или веб-версию —
там понятно, что это проба.
