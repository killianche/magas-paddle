# API

Адрес: `https://padel.217-114-8-196.sslip.io/api`
Код: `server/api` — NestJS + Prisma, как в docs/STACK.md.
Работает в контейнере `magas-api`, наружу проходит только через nginx.

## Что умеет

| Метод | Путь | Зачем |
|---|---|---|
| GET | `/api/health` | жив ли сервис и отвечает ли база |
| GET | `/api/courts` | площадки с тарифами; выключенные не отдаются вовсе |
| GET | `/api/availability?date=ГГГГ-ММ-ДД` | сетка «часы × площадки»: статус, цена и сколько часов подряд свободно |
| GET | `/api/bookings?phone=` | записи человека |
| POST | `/api/bookings` | создать запись |
| DELETE | `/api/bookings/:id?phone=` | отменить |
| GET | `/api/tournaments?phone=` | турниры, занятые места, записан ли этот человек |
| POST | `/api/tournaments/:id/entries` | записаться на турнир |
| DELETE | `/api/tournaments/:id/entries?phone=` | отменить запись |

Входа нет, человек опознаётся по номеру телефона — так решено в DECISIONS.md.

## Двойная бронь

База не даёт создать пересекающуюся запись. API ловит ошибку PostgreSQL `23P01`
и отвечает **409** с готовой заменой:

```json
{ "code": "slot_taken", "message": "Это время только что заняли",
  "alternatives": { "sameTime": [ { "courtId": "c2", "courtName": "Корт 2" } ],
                    "later": { "courtId": "c1", "hour": 20 } } }
```

Проверено на живом сервере: первая бронь Корт 1 на 18:00–20:00 создалась за 9 000 ₽,
вторая на то же время отклонена, в ответ пришли Корты 2, 3, 4 и время 20:00.

## Цены

Хранятся в копейках. Считаются по часам: игра с 17:00 на два часа — это дневной
час плюс вечерний, а не два одинаковых.

## Данные

`server/sql/seed.sql` — **заглушки**, ровно те же значения, что были зашиты
в приложении. Заменяются на данные клуба (вопросы Q1–Q8, Q44).

## Приложение подключено

Экраны читают данные с сервера, локальных заглушек больше нет —
`src/data.ts` и `src/store.ts` удалены. Появились:

- `src/api.ts` — единственное место, где приложение ходит в сеть
- `src/useApi.ts` — состояния «ждём / получили / не вышло» и обновление жестом
- `src/profile.ts` — имя и телефон, сохраняются на устройстве
- `src/dates.ts` — даты по времени клуба, без захардкоженного «2 сентября»

На экране заявки теперь настоящие поля имени и телефона: входа нет,
и сервер узнаёт человека по номеру. При следующей записи поля уже заполнены.

Проверено сквозным тестом на живом сервере (`scripts/tests/live.js`):
запись создаётся, видна в «Моих записях» со статусом «ожидает»,
отменяется; турниры приходят с сервера.

## Чего ещё нет

Раздел устарел и переписан 7 сентября: админка давно есть — подтверждение
заявок, отметка «не пришёл», карточка клиента, история, аналитика, оплаты,
цены, сотрудники и права. Описание — в docs/ADMIN.md.

Действительно нет до сих пор:

- **Уведомлений в любом виде.** Ни пушей клиенту, ни сигнала менеджеру
  о новой заявке. Менеджер узнаёт о заявке, только если у него открыта вкладка
  админки: она опрашивает сервер раз в минуту. Заявка живёт час и молча
  сгорает — это самая дорогая дыра из оставшихся.
- **Оплаты в приложении.** Деньги принимает менеджер, приложение только
  показывает сумму.
- **Листа ожидания** на занятый час.
- **Абонементов, депозитов и повторяющихся броней.**
- **Записи к тренеру** и проката при бронировании.
- **Турнир не занимает корты**: в день турнира те же часы продаются повторно.
- **Проверки номера кодом.** Кто знает чужой номер, видит и отменяет чужие
  брони: сервер сверяет только строку телефона.
